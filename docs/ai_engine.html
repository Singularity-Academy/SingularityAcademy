AI Engine API Documentation

Overview

The AI Engine provides a set of APIs for frontend applications to interact with AI functionalities. This documentation is intended for frontend developers who need to integrate with the AI Engine.

Note: All AI Engine routes are under the "/ai" prefix due to the application running behind a Caddy proxy.

Authentication

Most endpoints require authentication using JWT tokens. The token should be included in the request headers or as specified in individual endpoint documentation.

HTTP Request Authentication

For HTTP endpoints, include the JWT token in the Authorization header using the Bearer scheme:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJJRCI6IjEyMzQ1Njc4OTAiLCJleHAiOjE3MTYyMzkwMjJ9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

Example HTTP Request with Authentication

GET /ai/ai/health/ HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJJRCI6IjEyMzQ1Njc4OTAiLCJleHAiOjE3MTYyMzkwMjJ9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
Accept: application/json

Note: WebSocket connections require sending an authentication message after establishing the connection.

WebSocket Authentication Message Example

{
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJJRCI6IjEyMzQ1Njc4OTAiLCJleHAiOjE3MTYyMzkwMjJ9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c"

Important: The JWT token shown in these examples is for illustration only. Your actual tokens will be provided by the authentication system.

HTTP Endpoints

GET /ai/health

Health check endpoint to verify if the API is operational.

Authentication required: No

Response:

{
    "status": "healthy"
}

GET /ai/health/

AI-specific health check endpoint to verify if AI components are operational.

Authentication required: Yes

Response (Success):

{
    "health": "ok",
    "user_id": "user_id_value",
    "message": "AI components are healthy"
}

Response (Unauthorized):

{
    "error": "Authentication required for AI health check"
}

WebSocket Endpoints

WebSocket /ai/chat

WebSocket endpoint for streaming chat responses from the AI.

Authentication required: Yes (via initial message)

Connection Flow

  1. Establish WebSocket connection
  2. Send authentication message
  3. Receive authentication response
  4. Receive chat history (if available)
  5. Send and receive messages

Authentication Message Format

{
    "token": "your_jwt_token"
}

Authentication Response (Success)

{
    "type": "auth_success",
    "message": "Authentication successful",
    "user_id": "user_id_value"
}

Authentication Response (Error)

{
    "type": "error",
    "error": "Error message",
    "error_code": "ERROR_CODE",
    "status_code": 401
}

History Messages (Sent after successful authentication)

{
    "type": "history_messages",
    "messages": [
        {
            "role": "user",
            "content": "User message content"
        },
        {
            "role": "assistant",
            "content": "Assistant response content"
        },
        // Up to 10 most recent messages
    ]
}

Sending Messages

To send a message to the AI, use the following format:

{
    "type": "message",
    "content": "Your message here"
}

Receiving Responses

Responses from the AI are streamed in chunks with the following format:

{
    "type": "message_chunk",
    "content": "Partial response content",
    "is_final": false
}

The final chunk will have is_final set to true.

Error Response

{
    "type": "error",
    "error": "Error message",
    "error_code": "ERROR_CODE",
    "status_code": 400
}

Error Codes

Error Code Description
INVALID_AUTH_FORMAT Invalid authentication message format
INVALID_TOKEN Invalid or expired token
INVALID_TOKEN_CLAIMS Invalid token claims
USER_NOT_FOUND User not found in database

Courses API

The AI Engine provides endpoints for course-related operations. These endpoints are available under the /ai/courses prefix.

GET /ai/courses/all

Get all courses for the authenticated user.

Authentication required: Yes

Response:

{
    "courses": [
        {
            "id": 1,
            "name": "Introduction to AI",
            "description": "Learn the basics of artificial intelligence",
            "created_at": "2023-01-15T12:00:00Z",
            "owner_id": 123
        },
        {
            "id": 2,
            "name": "Machine Learning Fundamentals",
            "description": "Understanding core ML concepts",
            "created_at": "2023-02-20T09:30:00Z",
            "owner_id": 123
        }
    ],
    "count": 2,
    "timestamp": "2023-05-10T14:30:00Z"
}

POST /ai/courses/create

Create a new course.

Authentication required: Yes

Request Body:

{
    "name": "Introduction to Deep Learning",
    "description": "Explore the fundamentals of neural networks and deep learning"
}

Response:

{
    "id": 3,
    "name": "Introduction to Deep Learning",
    "description": "Explore the fundamentals of neural networks and deep learning",
    "created_at": "2023-06-15T10:45:00Z",
    "owner_id": 123
}

GET /ai/courses/{course_id}

Get a specific course by ID.

Authentication required: Yes

Parameters:

  • course_id - The unique identifier of the course (integer)

Response:

{
    "id": 1,
    "name": "Introduction to AI",
    "description": "Learn the basics of artificial intelligence",
    "created_at": "2023-01-15T12:00:00Z",
    "owner_id": 123
}

PUT /ai/courses/{course_id}

Update a specific course.

Authentication required: Yes

Parameters:

  • course_id - The unique identifier of the course (integer)

Request Body:

{
    "name": "Updated Course Title",
    "description": "Updated course description"
}

Response:

{
    "id": 1,
    "name": "Updated Course Title",
    "description": "Updated course description",
    "created_at": "2023-01-15T12:00:00Z",
    "owner_id": 123
}

DELETE /ai/courses/{course_id}

Delete a specific course.

Authentication required: Yes

Parameters:

  • course_id - The unique identifier of the course (integer)

Response:

{
    "message": "Course deleted successfully"
}
